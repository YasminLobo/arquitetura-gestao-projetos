Micro Frontends: dividindo a interface entre equipes independentes

Como organizar aplicações web grandes para que cada equipe seja responsável por uma parte completa do produto, do banco de dados até a tela.

Artigo original (martinfowler.com) ↗ Próximo: Camadas (Layering) →
Parte 1

Resumo da ideia central

Muitas empresas dividem o back-end em microsserviços para ganhar agilidade, mas continuam mantendo um único projeto gigante para o front-end. Na prática, essa interface única vira um gargalo: qualquer mudança no produto exige alinhar a equipe de front-end com várias equipes de back-end antes de publicar.

O conceito de Micro Frontends resolve isso aplicando a mesma ideia de independência para a interface. Em vez de separar as equipes por tecnologia (time de front-end vs. time de back-end), o sistema é dividido por áreas de negócio — como Busca, Catálogo de Produtos e Pagamento.

Assim, cada equipe cuida da sua funcionalidade de ponta a ponta e consegue atualizar sua parte da tela de forma autônoma, enquanto uma aplicação base (Container) junta todas essas partes para o usuário final.

Parte 2

Vantagens e desvantagens

Vantagens
  • + Publicações independentes: Uma equipe consegue corrigir ou atualizar sua parte da tela sem depender do restante do sistema.
  • + Códigos menores e mais fáceis de manter: Cada projeto front-end contém apenas o código daquela funcionalidade específica.
  • + Evolução gradual: Permite modernizar ou trocar tecnologias de uma área específica sem precisar reescrever o site inteiro.
Desvantagens
  • − Arquivos mais pesados para o usuário: Se cada equipe carregar suas próprias bibliotecas sem cuidado, o site fica mais lento para abrir.
  • − Risco de perda de padrão visual: Exige um guia de estilo compartilhado para que botões, fontes e cores não fiquem diferentes em cada parte.
  • − Maior trabalho de configuração: É preciso manter vários repositórios, rotinas de testes e processos de deploy separados.
Parte 3

Impacto na gestão do projeto

Prazo Ganho em escala

No começo exige mais tempo para estruturar a base que junta as telas. Depois de pronto, acelera o cronograma porque várias equipes conseguem entregar ao mesmo tempo sem fila de espera.

Custo Maior estrutura

Aumenta o custo com automação e manutenção de múltiplos pipelines. Só se paga em projetos grandes; para sistemas pequenos com pouca gente, gera gasto desnecessário.

Equipe Autonomia por área

Muda diretamente a forma de organizar as pessoas: em vez de um time só de front-end e outro só de back-end, formam-se equipes mistas focadas em cada área do produto.

Riscos Padrão e desempenho

Reduz o risco de uma atualização derrubar o site todo, mas exige que a gestão acompanhe de perto a padronização visual e o desempenho da página para o usuário.
